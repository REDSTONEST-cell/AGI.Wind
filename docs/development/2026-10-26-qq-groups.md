# QQ 群聊、连续接话与双记忆池（第一批）

日期：2026-10-26。依据：桌面《AGI.Wind：QQ群聊、连续接话与双记忆池开发说明》。本记录区分“已实现”“离线验证”“尚未完成”，不把群消息放开当作全部功能完成。

## 本轮已实现

### 1. 群窗口与发送者身份（迁移 0014）

- 新增 `channel_bindings`：`(account_id, companion_id, platform, bot_external_id, channel_kind, external_chat_id)` 唯一键。每个启用的 QQ 群对应一个持久会话窗口；首次收到消息时创建，服务重启后复用，创建群窗口不归档主人私聊或其他群。
- 新增 `external_principals`：`(account_id, platform, external_user_id)` 稳定成员身份。昵称、群名片只更新展示字段，改名不产生新的人；`sender.role` 只记录群内角色，不产生任何 AGI.Wind 权限。
- `events` 增加 `sender_principal_id`、`external_message_id` 与 `(conversation_id, external_message_id)` 部分唯一索引；`conversations` 增加 `channel_kind`（web/private/group）。
- 新增 `qq_message_receipts`：保存每条已发送文字/图片的 OneBot 回执 ID，引用机器人第二段或图片也能被识别。

### 2. 先归档、再决定是否回复

- `ArchiveService.record_external_message()` 只写事件，不创建请求、生成或模型任务；群消息重复上报由平台消息 ID 幂等去重。
- 需要回复时 `ArchiveService.submit_external_reply()` 复用同一条已归档事件创建 generation，不重复归档同一句话；回复目标群号来自绑定和触发事件，模型不能填写。
- 新增 `integrations/qq_groups.py`：OneBot 群事件标准化、群白名单、成员身份、持久窗口、发送回执。
- 新增 `integrations/qq_attention.py`：规则优先的接话判定。明确 @ 机器人、引用机器人已发送消息直接回复；机器人成功回复后 90 秒、最多 4 轮的短时窗口内，只有明确追问（为什么/怎么/那…呢/吗/？等）才继续；@ 别人、引用别人、没有信号或过期保持安静。无相关信号不调用模型，也没有新增每条消息的大模型费用。
- `QQBridge` 增加群路径：`send_group_msg`、逐段回执、群消息与私聊共用有界队列和现有分段/停止/审批链路；默认 `group_enabled=false`，只接入管理页明确列出的群。

### 3. 双记忆池与场景隔离

- `memory_items` 增加 `pool_kind`（owner/member）、`subject_principal_id`、`origin_room_id`、`visibility`、`visibility_room_id`。旧记忆迁移后默认主人私有，绝不默认公开或全群共享。
- 新增 `memory/access.py` 与 `SceneScope`：场景只由服务端根据会话 `channel_kind`/绑定构造，请求正文和模型不能扩大权限。
  - 主人私聊/网页：只取主人池；可回忆主人在群里说过的本人事实，但不取成员池、不取群聊原始切片。
  - 群 A：只取本群公开的主人事实与本群相关成员事实；群 B、主人私密事实、私聊原始内容都不出现。
- 提炼链路只把主人自己（或无发送者的旧数据）的发言作为主人池证据；群成员消息即使在同一群也不写入主人池。主人群发言写入主人池时带 `group_public` 与来源群；无法唯一确定来源群时保守回退为主人私有。
- 群场景的检索、关键词/语义候选、原文切片、上下文装配都使用同一可见性条件；群上下文最近消息带发送者标签，群场景不加载主人的关系快照与私密承诺。
- 导出/导入升级为 archive format 4（`0014_qq_channels`），新表进入权威归档顺序；旧格式归档仍可导入，缺失的群表按空处理，旧记忆默认私人。

### 4. 最小管理界面

- 连接页新增“启用 QQ 群聊”、允许群号列表、接话模式（智能接话 / 仅 @ 引用）、接话有效期与轮次。
- 侧栏新增“QQ 群”窗口列表，群窗口显示群名/群号；群窗口只读并显示发送者名片，切回“对话”回到私人窗口，两边历史不混。
- 状态文字区分“群消息已归档未触发回复”“该群未启用接入”“重复上报已忽略”。

## 离线验证

- 新增 `tests/integration/test_qq_groups.py`（5 项，模拟 OneBot WebSocket + 合成提供商）：群窗口持久化、主人私聊不被归档、重复上报不重复生成、无 @ 追问继续接话、过期不接、引用第二段触发、未列群忽略、重启后同一窗口和同一成员身份。
- 新增 `tests/integration/test_memory_scene.py`（3 项）：群 A/B 记忆检索隔离、主人池提炼只收主人发言且群事实标公开、群上下文发送者标签与主人关系/私密承诺隔离。

## 第二轮补充：成员池提炼与双池管理页

- 新增 [memory/members.py](app/src/agi_wind/memory/members.py)：成员池写入器。事实主体永远取被引用事件的服务端发送者身份，房间永远取任务绑定的群；同一候选若引用多个成员则进隔离区；只接受成员本人的 `user_asserted` 发言；同一成员同一谓词的相反说法标为 disputed 并建立 contradicts 关系，不做静默覆盖；主人发言、匿名/无身份消息不会进入成员池。
- 新增 outbox 任务 `memory.extract.member`：按群绑定独立游标批量读取非主人成员消息，预算受限地调用同一记忆提炼模型；群回复完成后立即入队，纯观察消息 60 秒合并入队（每群同时最多一个 pending 任务），避免每条群消息调用模型。
- `memory/retrieval.py` 列表接口增加 `pool`、`room_id`、`subject_principal_id` 过滤并返回群名/成员名片；统计增加 `pool_counts`；`GET /api/v1/integrations/qq/groups` 返回持久群窗口供筛选。
- 记忆页新增“记忆池”筛选（全部/主人记忆/群成员记忆）与来源群筛选；成员记忆标签显示“群成员 · 名片”和“来自 群名”，详情显示事实主体与来源群。
- 验证：成员池专项 3 项（主体/房间/池隔离、成员任务游标、API 双池列表）、QQ 群专项 6 项全通过；完整 pytest **351 passed, 3 skipped, 1 failed**（仍为既有通话 call_id 测试）；无头 Chromium 实测成员池筛选、名片/群标签与来源群下拉，0 JS 异常。

## 当前限制（下一批）

1. 真实 QQ 群收发尚未验收：需要用户在连接页填写至少一个真实群号并开启群聊，再做一次“甲 @ → 无 @ 追问 → 乙加入 → 丙闲聊不被抢答”的真实群验收。
2. 短时接话线程只保存在进程内，重启后回到普通观察；绑定窗口与成员身份持久，但“刚回复后的 90 秒”不延续。多个话题暂按每群单线程处理。
3. 成员池自动提炼已开启（见上方第二轮补充）；本次未用真实模型积累成员记忆，也没有对真实群历史做提炼验收。
4. 群消息暂不触发语音/主动消息；群内停止仅保留主人私聊 `/stop` 与网页停止，成员级停止、群内审批和工具预算尚未接入。
5. 接话只做规则判断，没有小模型歧义分类；跨成员代词（“他说的那个”）可能漏接，这是有意保守。
6. 群设置没有逐群独立启停开关，只有允许群列表；接话参数为全局值。
7. 导出/导入已包含新表，但真实历史归档与恢复只做了测试库往返，没有对现有大档案做一次完整恢复演练。
8. 成员池生命周期/纠正/删除目前复用通用记忆表能力，尚未做逐成员画像合并或跨群合并（按文档要求默认不合并）。
