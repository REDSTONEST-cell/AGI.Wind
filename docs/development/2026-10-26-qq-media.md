# QQ 多媒体、分段与发送节奏（2026-10-26）

## 范围

在 QQ OneBot 通道（私聊 + 已授权群聊）上完成图片、表情包、语音的接收与回复发送，并调整回复分段与发送节奏。代码由 Codex 完成后收尾，本轮补齐验证与交互修正。

## 实现

- 接收：`integrations/qq.py`、`qq_groups.py` 保留图片文件标识与 record 消息标识；图片复用 AssetStore 与 VisionAdapter，缺少 URL 时调用 OneBot `get_image`；语音复用当前 SnowLuma 的 `get_record_text(message_id)`，按原始 QQ 消息转写，不读取消息里的本机路径。
- 转写结果带 `[语音转文字]` 标签进入原有聊天/成员记忆隔离流程；原始语音不存档，不是重新部署本地 ASR。
- 图片下载只对白名单域名把 HTTP 升级 HTTPS，保留公网 DNS/IP 固定、防重定向、大小与真实格式校验。
- 回复：QQ 输入语音或文字要求“语音”时本轮申请 always，其余 auto，服从全局语音开关与概率；生成完成后最多等待 120 秒本轮后台合成（可被 Stop 取消）。
- 发送：语音以 record/base64、表情包/图片以 image/base64 通过 `send_private_msg` / `send_group_msg` 发出；有对应音频的段只发语音，不再重复发该段文字，文字仅作为合成失败或缺失时的回退；表情包附件 `kind=sticker` 按图片发送。
- 分段：不再按句号等标点自动切分。由模型自己决定条数，一行就是一条消息（`delivery/segments.py` 与客户端 `reply-segments.js` 同步），想发几条写几行。
- 节奏：QQ 每条文字按长度延迟 `0.6s + 0.06s/字`（上限 8 秒）再发下一条，语音/图片沿用原来的 0.6 秒；比固定延迟更接近真人打字。
- 表情包频率：Agent 回合不再每轮都提供表情包工具，每轮 30% 概率才注册 `search_stickers`/`send_sticker`；用户明确要表情包或发图时直接提供；模型拿到工具后自行决定是否发送。常量在 `agent/delivery.py` 的 `STICKER_TURN_CHANCE`。
