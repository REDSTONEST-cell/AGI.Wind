1. 先看这里：一分钟认识她

AGI.Wind 是一个本地优先的 AI 陪伴服务。前端是浏览器里的聊天客户端，后端是本机 Gateway；聊天记录、人格档案和记忆主要保存在本机 PostgreSQL 里。鱼丸是当前陪伴角色。

可以聊天

文字流式回复、按行分段的气泡、图片、语音、表情包；QQ 私聊也能用。

可以记住

人格档案、主人记忆、群成员记忆分开保存；记忆可查看来源、隐藏、纠正。

可以说话

本地 Breeze 克隆音色；语音消息与实时通话；QQ 语音消息会转写成文字再进入对话。

可以主动找你

长时间没聊天，或回复后你没有继续，她可以独处思考，再决定要不要主动开口。

最重要的一点：她不是“假装回复”的脚本。没有配置对话模型时，聊天的真实结果是明确报错，不会伪造回答；语音、图片、QQ 也各有清晰的失败提示。

2. 启动、打开与停止

2.1 正常启动

在项目根目录双击 启动本地服务.cmd，或者打开 PowerShell 执行：

cd C:\path\to\AGI.Wind
.\scripts\start-local.ps1

默认只监听本机；如果想让同一局域网里的其他设备访问，使用 启动服务端(局域网).cmd 或 .\scripts\start-local.ps1 -BindHost 0.0.0.0。

2.2 打开客户端

浏览器打开 http://127.0.0.1:18440/。本机回环访问会自动登录，不需要手动输入访问令牌。状态页是 http://127.0.0.1:18440/status。

2.3 查看状态与停止

双击 查看本地状态.cmd 查看各依赖是否运行；双击 停止本地服务.cmd 正常停止（会保留数据）。如果只想重启 Gateway，可先停止再启动，数据库默认保留。

4. 日常聊天

4.1 发送与停止

在底部输入框输入文字，按 Enter 发送，Shift+Enter 换行。生成过程中可以点停止按钮；点「⋯」里的归档会开始一段新对话，旧对话变只读。

4.2 分段与语音

  • 模型决定怎么分段：通常一行一个气泡，不再机械地按标点拆。
  • 输入框旁有「语音」开关。关闭时按概率（默认约 30%）随机带语音；打开后每条有正文的回复都尝试带语音。语音是独立气泡，可播放/暂停。
  • 隐藏的情绪标记会从文字中剥离，用来决定语气；它不会出现在聊天正文里。

4.3 图片与表情包

输入框左下角「＋」选择图片，或 Ctrl+V 粘贴，最多 4 张，可纯图片发送。图片会先经过识图，再生成回复。表情包可以在「表情包」页管理；她需要时会自己挑，不建议每轮都强制发表情。

4.4 运行日志

点聊天页右上角日志按钮，打开「她的活动」：

  • 默认只显示本次打开后的新活动，每次回复或独处思考折叠成一张卡片；
  • 点开卡片可以看到“她在想什么、翻了什么记忆、做了什么动作”；
  • 工具名会翻译成人话（翻记忆、上网查、挑表情包等）；HTTP/事件 ID/内部技术字段默认隐藏；
  • 右上角「看原始日志」可切回完整终端视图，便于排查问题；错误和警告会保留并展开。

5. QQ 使用

5.1 接入前提

QQ 聊天由外部的 SnowLuma 接入端负责登录和 OneBot v11 协议，AGI.Wind 不保存 QQ 密码。打开 http://127.0.0.1:5099 完成 SnowLuma 的 EULA 和 QQ 登录，然后在网页「连接 → QQ · 与鱼丸私聊」里填写：

  • 主人 QQ 号、鱼丸 QQ 号；
  • 反向 WebSocket 地址（同机通常是 ws://127.0.0.1:18440/api/v1/integrations/qq/ws）；
  • 至少 32 位连接令牌，并复制到 SnowLuma 的 Access Token；
  • 把绑定对话选为网页当前对话。
只响应主人：QQ 私聊固定只认绑定的主人 QQ；群聊必须逐群填写并启用，不会因为“在群里说过话”就获得主人权限。

5.2 私聊：等你把话说完

鱼丸不会在你第一句话刚落下时立刻抢答。私聊连续发来的几句话会先进入 消息防抖：

  • 默认：你停下后等 2.2 秒；看起来说完了，再等 0.9 秒确认；最多等你 8 秒。
  • 如果句尾是逗号/顿号/“然后、还有、因为……”等，说明没说完，她会继续等；最多到硬上限。
  • 最多合并 8 条 / 4000 字；这些碎片会变成一个回合，只触发一次思考。
  • 图片、语音、命令会先结束当前文字批次，避免顺序颠倒。
  • 等待期间不占用生成 worker；发「停止」会取消还没提交的批次。

参数可在「连接 → QQ」里调整：说完后等待、最多等到、最终确认等待、每段基础等待、两条最少间隔、每轮最多几段。

当前边界：防抖目前只对主人私聊的纯文字生效；群聊仍按原逻辑逐条处理，以免打乱群消息顺序和接话判断。

5.3 发送节奏

她回复时不会一口气把 8 条消息甩出来。每段之前会按文本长度做对数曲线等待，并加一点随机抖动；默认基础等待 1 秒、两条最少间隔 1.8 秒、单段最长 8 秒、每轮最多 8 段。你原来的基础值 0.6 秒会保留，但已经叠加了曲线和最小间隔，所以会比以前明显慢。

觉得太快，可在 QQ 设置里把「每段基础等待」调到 1.2–1.5 秒；觉得太慢可调回 0.8 秒左右。设为 0 会关闭等待，仅建议调试使用。

5.4 群聊

  • 群聊默认关闭，只接入「允许的群号」列表中的群；每个群一个独立窗口。
  • 接话模式：「智能接话」在她刚回复过的短窗口内判断明确追问；「仅 @ / 引用」只响应 @她或引用她消息。
  • 其他群消息仍会作为上下文观察和成员记忆来源，但在未触发回复时不调用对话模型。
  • 群内成员使用独立成员记忆，不会写进主人私密记忆池；匿名消息不会提炼成员记忆。
  • 连接页的群窗口列表可以逐群启停；关闭后该群消息不再触发回复和成员记忆。

在 QQ 里发 /stop 或 停止 可以停止当前回答和待发送内容；主人私聊与群聊共用这个入口。

6. 人格与记忆

6.1 灵魂档案

「灵魂档案」决定她是谁：名字、身份、性格、说话方式、背景、与你的关系、你的称呼等。它也包含双方头像：她的头像和“你的头像”分开设置，选图后可拖动/缩放裁剪，保存档案后生效。

  • 档案有版本号；保存时如果旧格式长文本会重复进入上下文，页面会提醒。
  • 修改人格或记忆后，正在进行的生成可能被取消，避免用旧人格继续回答。

6.2 记忆页

「记忆」页不是只读摆设：

  • 列表与搜索：按正文或来源原文搜索；按类型、状态、时间筛选；显示重要度、来源数、访问次数和到期时间。
  • 来源与纠正：每条记忆能展开来源引文；纠正时会生成新记忆并保留旧版本，不会直接篡改历史。
  • 隐藏/恢复：隐藏后不再被召回，但原始对话不会删除；恢复后重新参与。
  • 记忆池：主人私聊的记忆和群成员记忆分池保存；群内还可以按来源群筛选。
  • 生命周期：不同类型有不同保留期；长期不用的记忆会衰减/过期，但正文和来源仍保留，不物理删除。可以手动“运行维护”。
  • 立即提炼：不必等下一轮聊天，可以手动让后台处理最近一批历史事件。
怎么让她记住？直接说“记住：我习惯用 Asia/Shanghai 时区”这类明确请求，系统会优先写入；普通聊天由后台自动提炼，不保证每句都变成长期记忆。

7. 语音与实时通话

7.1 语音回复

「模型与语音」里可以设置语音开关、概率、音色和试听。当前使用本地 Breeze TTS 的 yuwan 克隆音色。语音回复与文字并存：文字始终保留，语音是额外气泡；语音失败不影响文字。

QQ 私聊/群聊也支持语音：收到语音消息时，通过 SnowLuma 转写成文字，并带「[语音转文字]」标记进入对话；回复语音时会等待本轮后台合成，最长约 120 秒，失败则回退文字。

7.2 实时通话

聊天输入栏旁的「通话」按钮进入实时语音通话：麦克风 → 本地 ASR → 对话 → 流式 TTS 播放。支持自然打断（插话）；通话期间不会同时发送主动消息。

通话依赖 ASR（8139）和 TTS（8137）服务。如果按钮不可用或提示未配置，先看「模型与语音」和本机服务状态。

8. 图片、表情包与 Agent 工具

8.1 图片

支持 PNG/JPEG/WebP/GIF，最多 4 张，可纯图片发送。图片会先被识图模型观察；历史、归档和重新打开都能看到原图。

8.2 表情包

表情包库支持上传、自动标签、改名、隐藏/恢复、删除。她可以根据上下文挑一张发出来；普通聊天里概率较低，避免每轮都发表情；你明确要表情包时概率更高。删除表情包不会删除已经发过的聊天图片。

8.3 Agent 能力

「Agent 能力」页可以按需开启：

  • 记忆查询：从当前场景允许的记忆池里检索；
  • 联网搜索：搜索摘要与来源链接，不会把搜索结果当指令；
  • 表情包查询/发送；
  • 文件读取/写入、命令执行（仅桌面私聊，默认受审批和目录限制；群聊强制关闭）；
  • 工具调用次数、时间、结果大小和预算上限。
权限提醒：群聊永远不继承主人的本地文件/命令权限。命令执行可能修改文件或联网；逐次批准模式下每次都要你确认。拒绝后她应停止该操作，不应反复索要批准。

工具过程只在日志里显示，不会把思考或工具 JSON 塞进聊天正文；日志的「原始日志」可以看到细节。

9. 主动消息与独处思考

主动行为分两种，设置页里可以分别调整；总开关仍是「主动消息」。

长时间没聊天

沉默达到设定空闲时间、且今天没超上限、不在安静时段，她可以主动发一条短消息。原设置的空闲/间隔/每日上限继续生效。

回复后独处

你回复完后约 150 秒没继续，她会先自己想一想（有限轮/步），再决定主动开口还是保持安静。默认最多 2 轮、4 步、每天 6 次。

  • 你在这段时间里发了新消息、按了停止、归档/删除会话，待执行的独处思考会取消。
  • 安静时段（默认 23:00–08:00）和每日上限对所有主动消息生效，避免半夜打扰或刷屏。
  • 独处时可以按开关使用只读工具（记忆/表情包/联网）和选择语音/表情；群聊目标受群权限限制。
  • 不想被打扰：关闭总开关，或把“回复后独处”关掉；也可以随时在 QQ 里发停止。

10. 模型、设置与外观

10.1 模型与语音

按能力卡配置：计划/对话模型、识图、语音转文字、文字转语音、嵌入、重排序。对话、识图、本地 Breeze 语音是当前主要可用能力；其余若未接入，页面会明确标注“待接入”，不要把它们当成已验收功能。

密钥只保存在服务端（data/secrets.json），页面只显示脱敏状态；保存后热加载，不需要重启。未配置对话模型时发送消息会明确提示，不会编造回答。

10.2 上下文预算

默认总上下文约 48 KB、单条输入约 12 KB。人格档案和输入分别计入预算；超限会给出可操作提示，不会假装是模型故障。

10.3 外观与账户

浅色、深色、跟随系统三种主题；桌面端和手机端都有响应式布局。侧栏底部会显示本机状态。主题和部分界面偏好会保存在浏览器本地；聊天内容不写 localStorage。

10.4 QQ 与主动消息设置

QQ 设置包括主人/机器人 QQ、反向 WS 地址、令牌、私聊/群聊开关、群白名单、接话模式、防抖与发送节奏。主动消息设置包括长空闲参数、回复后独处参数、安静时段、每日上限、QQ 追话/工具/媒体开关和一个独处工具调用预算。

11. 归档、备份、隐私与安全

11.1 归档与删除

  • 归档：旧对话变只读，保留可回看；恢复会把当前对话归档，确保同时只有一段活动对话。
  • 永久删除：会写入独立删除账本，清除该对话的事件、请求/生成、附件引用及由它产生的记忆来源，无法恢复。
  • 删除事件/消息会同时处理派生输出和未共享媒体；共享素材可被其他消息保留。

11.2 导出与恢复

项目根目录下可执行（示例）：

.\app\.venv\Scripts\python.exe -m agi_wind.cli archive export --output data\exports\manual.zip
.\app\.venv\Scripts\python.exe -m agi_wind.cli archive verify data\exports\manual.zip
.\app\.venv\Scripts\python.exe -m agi_wind.cli archive import data\exports\manual.zip --mode clone --latest-ledger data\governance

导出包用于迁移对话/人格/记忆等公开档案；它不包含 API 密钥、QQ 令牌、完整数据库或语音参考文件。恢复默认用新的命名空间和删除账本，不能拿旧备份覆盖新的删除记录。

11.3 哪些文件绝不能发出去

data/local-db.json、data/access-token.txt、data/secrets.json、data/settings.json 以及 QQ/模型令牌都属于秘密或本机配置；不要把 data 目录整体发到群里或公开仓库。

文件说明：data/assets 是媒体，data/dev-postgres 是数据库目录，运行中直接复制不等于有效备份；要按官方导出/备份流程做。

11.4 安全

本机回环访问自动登录；对外访问请使用 HTTPS（Caddy 已在本机运行）并更换默认客户端密钥。公开网络不要直接暴露 18440/55432/5099。QQ 连接令牌只给 SnowLuma，不写进浏览器存储。

12. 常见问题与排查

13. 当前边界

  • QQ 防抖只覆盖主人私聊纯文字；群聊不聚合，图片/语音/命令不进入文字批次，避免顺序和权限问题。
  • 防抖批次是内存态：Gateway 崩溃/重启会丢失尚未提交的少量碎片；这不会影响已经落盘的历史。
  • 真实环境验收：QQ 连接依赖 SnowLuma 登录和网络；大体量群聊、不同 QQ 客户端版本、真实麦克风/扬声器等仍以实际使用为准。
  • 部分能力待接入：嵌入/重排序等模型角色、Live2D、NAS 部署等尚未作为完整验收项；页面标注“待接入”的不要当作可用。
  • 主动消息与独处：受安静时段、每日上限、工具权限和 QQ 目标绑定约束；不是无限自主动作。
最后记住三件事：
1）聊天、语音、QQ 都是增强项，文字和档案是核心；
2）让她慢一点、像人一点，可以调 QQ 的“防抖 + 发送节奏”，不用改代码；
3）遇到异常先看状态页和“她的活动”，需要细节再开原始日志。
