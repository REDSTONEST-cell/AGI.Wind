# 实时语音通话实施计划

> 2026-10-26：TTS 已从“客户端切块 + 每块一次 HTTP 合成”改为 **Breeze WebSocket 流式会话**（文本增量直接喂给 Breeze、按句连续出 PCM），并归一化中文全角标点；假麦克风 Chromium 验证音频排期连续、0 JS 异常。详见 [通话流式合成改造](../development/2026-10-26-call-streaming.md)。

用户已要求直接实现。目标是持续收音、流式字幕、自动接话、流式播放与插话打断；延迟目标不是实测承诺。

架构：独立 CPU ASR 进程（sherpa-onnx 中文流式 Zipformer INT8 + Silero VAD），只监听回环。Gateway 用认证 API 签发一次性 30 秒通话票据，以 WebSocket 中继音频与识别事件。聊天沿用现有档案/人格/记忆/SSE，关闭普通语音合成，按正文句段向 Breeze 请求 PCM 流，浏览器即时播放。所有模型推理与网络等待不得阻塞 Gateway 主循环。

- [x] 先测票据单次消费/过期、通话接口认证/CSRF与断连清理。
- [x] 部署独立 ASR 环境/模型，测真实音频分块识别速度与 VAD。
- [x] 接入 Gateway 中继、语音流、取消/排队上限。
- [x] 接入麦克风 AudioWorklet、回声消除、字幕、通话/静音/挂断；插话清播放队列、取消旧生成，epoch 丢弃迟到音频。
- [x] 定向测试、真实服务识别与 TTS 首包；操作手册与服务健康检查。
- [ ] 用户实际麦克风、扬声器/耳机与完整人格上下文的主观通话验收。

约束：保留桌面工作区现有改动，不整体合并旧 worktree；录音不默认落盘；临时识别不进聊天档案，最终文字才写入；思考/工具日志沿用现有隔离；没有真实麦克风通话验收不得宣称真人级延迟已达标。局域网麦克风需 HTTPS 安全上下文。

实施裁定：通话请求增加 output.realtime=true，使用增量正文路径，跳过非流式 Agent 工具规划；只对已验证的官方 DeepSeek 新模型关闭通话请求的 thinking，不改普通对话的模型配置。原生工具操作仍通过文字聊天进行。通话 device_id 由服务器签发并与 WebSocket 绑定，断连后服务端取消该会话的未完成生成，禁止已结束会话的迟到 HTTP 请求。

审查修复：ASR reset 保持句子编号单调；TTS 增加 credit 流控；授权等待阶段即启用心跳与断连清理；挂断在 await 前完成界面清理，避免旧 close 隐藏重拨界面；服务端跟踪通话生成归属。保留普通聊天旧请求 hash。
